# 记忆服务环境配置使用说明

## 1. 配置文件位置

源码只提供不含密钥的模板：

```text
clawcodex_ext/latent_memory/server/memory.env.example
```

真实配置默认放在用户状态目录，不要提交到 Git：

```text
Windows: C:\Users\<用户名>\.clawcodex\memory\memory.env
Linux/macOS: ~/.clawcodex/memory/memory.env
```

PowerShell 初始化示例：

```powershell
$stateDir = Join-Path $HOME ".clawcodex\memory"
New-Item -ItemType Directory -Force $stateDir | Out-Null
Copy-Item `
  "D:\gitcode\clawcodex\clawcodex_ext\latent_memory\server\memory.env.example" `
  (Join-Path $stateDir "memory.env")
notepad (Join-Path $stateDir "memory.env")
```

`clawcodex-dev memory enable/restart/serve` 会自动加载该文件。普通
`clawcodex-dev` 启动时只从中导入 `CLAWCODEX_PASSIVE_MEMORY*` 变量，不会把
记忆服务的 `OPENAI_API_KEY` 或 `OPENAI_BASE_URL` 注入主模型进程。

执行 `memory enable`、`memory restart` 或 `memory serve` 时，还会在当前项目生成
被 Git 忽略的 `.mcp.json`，并把当前项目 `.env` 中的
`CLAWCODEX_PASSIVE_MEMORY` 设为 `1`。执行 `memory disable` 会删除其中由记忆
模块管理的 MCP 项并把开关设回 `0`。

`memory serve` 是临时的前台运行模式。服务正常退出或按 `Ctrl+C` 关闭后，会自动
删除当前项目 `.mcp.json` 中受管的 `latent-memory` 项，并把当前项目 `.env` 中的
`CLAWCODEX_PASSIVE_MEMORY` 设回 `0`。如果开关仍为 `1` 而服务已经不可访问，
被动记忆只输出一次警告并降级为无记忆模式，不会打印连接异常堆栈或阻断正常对话。

### 配置优先级

记忆服务配置优先级从高到低为：

1. 当前进程环境变量；
2. `--env-file`；
3. `CLAWCODEX_MEMORY_ENV_FILE` 指向的文件；
4. `~/.clawcodex/memory/memory.env`；
5. 当前项目 `.env`；
6. 代码内置默认值。

配置文件修改后必须执行 `memory restart`。已经运行的后台进程不会自动重载。

### 查看日志
```
clawcodex-dev memory logs -f
```

### 清除历史

```
curl.exe -X POST http://localhost:8888/reset/factory
```

## 2. 云端 OpenAI 兼容模型

至少修改以下字段：

```dotenv
CLAWCODEX_PASSIVE_MEMORY=1

LLM_PROVIDER=openai
LLM_MODEL=你的抽取模型名
OPENAI_BASE_URL=https://你的服务地址/v1
OPENAI_API_KEY=你的记忆服务密钥

EMBEDDER_PROVIDER=openai
EMBEDDER_MODEL=你的向量模型名
EMBEDDING_DIMS=向量维度
```

`OPENAI_BASE_URL` 可指向 OpenAI 兼容网关。它只控制 Mem0 抽取与 embedding，
不修改 ClawCodex 主 Agent 的 provider。主 Agent 仍由
`C:\Users\<用户名>\.clawcodex\config.json` 控制。

可修改以下字段：
```
# 注入记忆允许的最低相似度
CLAWCODEX_PASSIVE_MEMORY_MINIMUM_SCORE=0.30
# 允许注入的最低分 = 最高分 - margin
CLAWCODEX_PASSIVE_MEMORY_SCORE_MARGIN=0.10
```

## 3. 本机 Ollama

例如使用本机 `qwen2.5:1.5b` 和 `snowflake-arctic-embed2:568m`：

```dotenv
CLAWCODEX_PASSIVE_MEMORY=1

LLM_PROVIDER=ollama
LLM_MODEL=qwen2.5:1.5b

EMBEDDER_PROVIDER=ollama
EMBEDDER_MODEL=snowflake-arctic-embed2:568m
EMBEDDING_DIMS=1024

OLLAMA_BASE_URL=http://127.0.0.1:11434
OPENAI_API_KEY=
```

修改 embedding 模型时必须同步填写真实 `EMBEDDING_DIMS`，否则 Qdrant
collection 维度可能与模型输出不一致。已存在 collection 的维度不会自动改变；
测试新模型时建议使用新的 `COLLECTION_NAME` 或新的状态目录。

## 4. 显著性门控

默认启用规则层，不调用模型：

```dotenv
SALIENCE_GATE_ENABLED=true
SALIENCE_GATE_OLLAMA_MODEL=none
```

需要 Tier 2 Ollama 判断时：

```dotenv
SALIENCE_GATE_OLLAMA_MODEL=qwen2.5:1.5b
SALIENCE_GATE_OLLAMA_BASE_URL=http://127.0.0.1:11434
```

完全关闭门控：

```dotenv
SALIENCE_GATE_ENABLED=false
```

## 5. 结晶与固化

两项高级能力默认关闭。启用 Ollama 结晶：

```dotenv
CRYSTALLIZE_ENABLED=true
CRYSTALLIZE_LLM_PROVIDER=ollama
CRYSTALLIZE_OLLAMA_MODEL=llama3.2:3b
CRYSTALLIZE_OLLAMA_BASE_URL=http://127.0.0.1:11434
```

启用 OpenAI 兼容结晶：

```dotenv
CRYSTALLIZE_ENABLED=true
CRYSTALLIZE_LLM_PROVIDER=openai
CRYSTALLIZE_OPENAI_MODEL=你的模型名
CRYSTALLIZE_OPENAI_BASE_URL=https://你的服务地址/v1
CRYSTALLIZE_OPENAI_API_KEY=你的密钥
```

固化层与结晶层共用 `CRYSTALLIZE_ENABLED` 开关。启用结晶后，可继续调整固化投影方式：

```dotenv
SOLIDIFY_PROJECTION_MODE=async
```

旧模板中的 `SOLIDIFY_ENABLED` 和 `SOLIDIFY_DUAL_WRITE` 当前不再被代码读取；
是否启用固化层只由 `CRYSTALLIZE_ENABLED` 决定。

**固化层提供版本追踪与回溯能力，端点如下**：

| 需求 | 接口 | 是否修改当前状态 |
|---|---|---|
| 查看当前 crystal 列表 | `GET /crystals` | 否 |
| 查看单条 crystal 的全部 revision | `GET /crystals/{crystal_id}/history` | 否 |
| 查看当前 head 派生的成熟度 | `GET /crystals/{crystal_id}/maturity` | 否 |
| 查看全体 crystal 在某个 rev/time 截止点的快照 | `GET /crystals?as_of=...` | 否 |
| 单条回到指定 `version` | `POST /solidify/rollback` | 是，只移动该条 head |
| 单条回到指定全局 `rev_id` | `POST /solidify/rollback` | 是，只移动该条 head |
| 撤销一个结晶 `batch_id` | `POST /solidify/rollback` | 是，移动或摘除该批次涉及的多个 head |
| 检查 head 与投影状态 | `GET /solidify/state`、`GET /solidify/preflight` | 否 |
| 从 Ledger 重建派生投影 | `POST /solidify/rebuild` | 是，只重建投影，不改变 head/history |

**`GET /crystals/{id}/history` 返回的每条 revision 主要包含：**

| 字段 | 含义 |
|---|---|
| `rev_id` | 全局递增 revision ID，也是最精确的逻辑时间游标 |
| `crystal_id` | crystal 的稳定身份，跨版本不变 |
| `parent_rev` | 当前 revision 的父 revision，用于重建实际分支 |
| `batch_id` | 产生该 revision 的一轮结晶或状态迁移批次 |
| `version` | crystal 分支上的易读版本号 |
| `op` | `create`、`absorb`、`repair`、`promote`、`retract` 等操作 |
| `status` | `candidate`、`active`、`canonical`、`disputed`、`superseded`、`retracted`、`expired` 等状态 |
| `body` | 该版本的知识正文 |
| `asset` / `facets` | 结构化资产与补充特征 |
| `source_ids` | 支撑该知识的 raw memory ID |
| `valid_from` / `valid_to` | 事实有效时间范围 |
| `recorded_at` | revision 写入 Ledger 的时间 |
| `actor` / `rationale` / `audit` | 操作来源、原因与审计数据 |
| `scope` | `user_id`、`agent_id`、`run_id` 等隔离范围 |

## 6. 启动与生效

保存配置后执行：

```powershell
clawcodex-dev memory restart
clawcodex-dev memory status
clawcodex-dev memory logs --lines 100
clawcodex-dev
```

`status` 应显示由数字组成的 PID。若显示 `pid external`，说明 8888 端口上运行的
是外部服务，当前配置文件不会控制该进程。

使用其他配置文件时仍可显式指定：

```powershell
clawcodex-dev memory restart --env-file D:\private\memory-production.env
```

`--env-file` 只作用于该次 `memory` 子命令。如果自定义文件中还包含被动记忆开关，
并希望普通 `clawcodex-dev` 也自动读取它，应通过
`CLAWCODEX_MEMORY_ENV_FILE` 指定固定位置；否则优先使用默认 `memory.env`。




## 7. 安全注意事项

- 不要把真实 `memory.env`、API Key 或私有 URL 提交到 Git。
- 源码目录只保留 `memory.env.example`。
- 建议记忆服务使用独立 API Key，方便限额、审计和撤销。
- 日志默认不输出 API Key，但提交日志前仍应人工检查。

## 8. 快速验证

```powershell
clawcodex-dev memory status
clawcodex-dev memory mcp --self-test
```

启动 ClawCodex 后发送一个唯一事实，等待被动日志出现
`capture_ready`、`write_started`、`write_completed`；新会话再次询问该事实，应看到
`recall_completed ... injected=true`。

布尔值除特别说明外使用 `true` / `false`。修改服务端变量后需要执行
`clawcodex-dev memory restart`；仅修改 `CLAWCODEX_PASSIVE_MEMORY_*` 时，重新启动
普通 `clawcodex-dev` 即可。
