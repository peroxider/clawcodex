# ClawCodex Layer 1 迁移需求详情

> 基于 `docs/clawcodex-初始上库-Layer1划分详情.md` 提取，每 Part 对应一个需求详情。
>
> 每个需求包含：**需求背景**（一句话）、**需求描述**（两句话，描述实际提供的能力而非迁移行为）、**需求价值**（一句话）。

---

## P1 — L1 Agent 核心

### 需求背景

Agent 运行循环、工具系统和远程会话是 clawcodex 扩展层的核心运行时，需要从上游解耦为独立可维护的 Layer 1 模块。

### 需求描述

提供 Agent 主循环与对话状态管理，支持多轮对话的暂停/恢复和会话生命周期控制。提供完整的工具系统（工具注册、执行沙箱、参数校验、结果格式化），以及远程会话桥接能力，使 Agent 可附着到远程运行时执行工具。

### 需求价值

建立 Agent 核心的可独立迭代边界，使工具系统和代理循环的二次开发不再侵入上游 `src/`，降低上游合并冲突风险。

---

## P2 — L1 Command/Query/Bridge/Providers

### 需求背景

命令系统、查询引擎、桥接层和 LLM 提供者是扩展层与用户交互及后端通信的关键管道，当前嵌在上游中需要剥离。

### 需求描述

提供可扩展的斜杠命令框架（命令注册、参数解析、权限校验、执行分发），支持用户通过 `/model`、`/provider` 等命令运行时切换配置。提供统一的 LLM Provider 抽象层，覆盖 100+ 模型后端的调用、流式响应、重试和降级策略；提供跨会话桥接层，支持多 Agent 会话之间的消息转发和状态同步；提供查询 Hook 引擎，支持在 Agent 响应链中插入自定义回调。

### 需求价值

解耦命令和查询体系，使 provider 扩展和桥接协议升级可独立于上游发布，提升团队协作效率。

---

## P3 — L1 Services Group A + Buddy

### 需求背景

MCP 服务、语音/频道/IM 网关和 Buddy 助手是高价值但高度耦合的附属服务，需要从上游中独立出来。

### 需求描述

提供 MCP（Model Context Protocol）服务器能力，让 Agent 可通过标准协议接入外部工具和数据源。提供语音合成/识别服务、多频道消息路由（Slack/Discord 等）和 IM 网关统一接入层，使 Agent 可在不同通讯平台上以语音或文本形式与用户交互。提供 Buddy 助手轻量级对话界面，支持快捷指令和快捷操作。

### 需求价值

释放 MCP 和音视频通道服务的独立开发和测试能力，避免对上游 Agent 循环的连锁影响，支撑多会话和多模态场景的快速迭代。

---

## P4 — L1 Services Group B

### 需求背景

30 个轻量/工具类 services（compact、templates、tool_execution、ultraplan、swarm、chrome 等）零散分布在上游 services 目录中，维护和扩展效率低。

### 需求描述

提供对话历史压缩（compact）和模板渲染引擎（templates），降低长对话的 token 消耗。提供工具执行的沙箱化运行环境（tool_execution）、超长任务规划引擎（ultraplan）、多 Agent 协同 swarm 编排和浏览器自动化（chrome）。提供技能搜索（skill_search）、上下文崩塌防护（context_collapse）、时间感知调度（kairos）、Langfuse 可观测性集成等能力。

### 需求价值

将零散的服务组件统一归入 Layer 1 管理，消除上游 services 目录的"大杂烩"状态，使每个小服务可独立迭代和测试。

---

## P5 — L1 CLI 与入口层

### 需求背景

CLI 命令分发、入口点、native 集成和 daemon 进程管理是 clawcodex 的用户界面门户，需从上游源码中剥离。

### 需求描述

提供多入口点启动框架（TUI 交互模式、Headless 非交互模式、MCP 服务模式、Orchestrator 守护进程模式、Daemon 后台运行模式），用户可通过单一 `clawcodex-dev` 命令统一调用。提供 CLI 子命令系统（`orchestrator server`、`issue list` 等）、native 平台集成（系统通知、剪贴板）和运行时环境管理（Python 版本校验、依赖检查）。

### 需求价值

解耦 CLI 入口层，使命令行界面和 daemon 的二次开发不触及上游核心，支持多入口点并行演进。

---

## P6 — L1 TUI/REPL/前端

### 需求背景

TUI 终端界面、REPL 交互循环和前端组件是用户与 Agent 交互的主要界面层，体量大且独立性强。

### 需求描述

提供基于 Textual 的富终端 UI（多面板布局、会话列表、日志查看器、Markdown 渲染），支持鼠标交互和键盘快捷键。提供 REPL 交互循环（流式输出、多行输入、命令补全、配色主题系统），以及前端调试面板（诊断信息展示、性能指标实时显示）。

### 需求价值

隔离 UI 层与 Agent 逻辑，使 TUI/REPL 主题定制、配色调试和前端增强不破坏核心 Pipeline，提升界面层的开发敏捷性。

---

## P7 — L1 权限/鉴权/钩子

### 需求背景

权限控制、鉴权 OAuth、钩子系统和进程引导是安全与扩展性的基础能力，当前在上游中维护不够灵活。

### 需求描述

提供细粒度的权限控制系统（工具级、文件系统级、网络级权限声明和审批），用户可自定义 Agent 能访问的资源和操作。提供多 Provider OAuth 鉴权（GitHub、Gitee、GitCode 等）和 API 密钥管理。提供基于 pluggy 的钩子系统，允许三方扩展在 Agent 生命周期的关键节点（工具执行前/后、消息发送前/后、会话创建/关闭）注入自定义逻辑。

### 需求价值

建立可插拔的权限与鉴权层，使安全策略和钩子扩展可独立于上游发布，支撑企业级部署和第三方集成。

---

## P8 — L1 智能子系统

### 需求背景

技能系统、上下文引擎、目标规划、意图预测、思维链等智能子系统是 clawcodex 区别于上游的核心增值能力，体量大（12 个子模块共约 34K impl）。

### 需求描述

提供技能系统（技能注册、匹配、热加载），让 Agent 按需加载领域特定能力。提供上下文构建与压缩引擎，在长对话中智能保留关键信息并丢弃噪声。提供目标规划与分解（goal）和意图预测（intent_forecast），使 Agent 能主动推断用户下一步需求。提供多模型路由（multimodel），根据任务复杂度自动选择最优 LLM。提供记忆目录（memdir）、离线摘要（away_summary）和思维链引擎（dreaming），增强 Agent 的长期记忆和深度推理能力。

### 需求价值

解耦所有增值智能子系统为独立 Layer 1 模块，使技能编排、上下文压缩、目标追踪等功能可独立开发、测试和迭代，保护 clawcodex 的核心竞争力。

---

## P9 — L1 调度/基础设施

### 需求背景

工具函数、定时任务、任务系统、配置管理、状态管理、编排器等基础设施贯穿项目全局，是各 Layer 的公共支撑。

### 需求描述

提供分布式定时调度系统（cron_system），支持分布式锁、抖动调度和 NDJSON 运行历史记录，可定时轮询 Issue 跟踪器并触发 Agent 任务。提供任务系统（tasks），支持任务定义、排队、执行和结果回调。提供统一的配置管理（configuration/settings/feature_gate），支持多层级配置合并（默认→用户→环境变量→CLI 标志）和渐进式功能开关。提供状态持久化（state）和跨模块消息总线（messaging），为 Orchestrator 编排器提供基础运行环境。

### 需求价值

建立稳固的基础设施层，使调度、配置和编排能力可独立于业务模块演进，为上层特性提供稳定的底层支撑。

---

## P0 — L1 补丁系统

### 需求背景

下游 fork 在官方上游之上维护补丁文件，覆盖所有扩展代码。

### 需求描述

提供补丁，将官方增量合入真实运行的扩展模块（而非仅合入门面文件），处理语义冲突（如 Headless 工具过滤、Query 循环增强、Bash 语义变更）。

### 需求价值

下游补丁始终可独立重建出完整 `src/`。
