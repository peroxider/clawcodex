传统流程
5 步手动接力 · 平均 3-5 天
  • 1
    开发者 triage issue
    每天人工看新 issue、分配优先级
  • 2
    写代码 + 跑本地测试
    本地 lint + 测试，发现 bug 再回头修
  • 3
    提交 PR 等 review
    reviewer 几小时后回来，可能要求改 3-5 轮
  • 4
    修 review 反馈
    每个 PR 平均 3.2 轮 review 修改
  • 5
    CI 失败后再修
    CI lint / 测试失败 → 又一轮反馈循环
Orchestrator
5 步全自主 · 平均 8-15 分钟
  • 1
    守护进程轮询 issue
    每 30s 一次，按 label / state 自动匹配
  • 2
    Agent 在 workspace 内改代码
    30 轮 QueryRunner，工具权限预授权
  • 3
    三道验证关卡
    test/build/lint，失败阻断 push
  • 4
    自动 push + 开 PR
    commit 写好、PR body 渲染完整
  • 5
    PR 评论 → 自动跟进
    扫描 review / CI 反馈 → 自动开下一轮 agent

pipeline 中的关键拐点

验证门控 ·
阻断 push 的关卡

整个 pipeline 唯一会阻断 push 的阶段。三道关卡顺序执行，任一失败 → commit 保留 · push 阻断 · issue 标 verification_failed。

// pipeline 13 stages · 第 9 步 = 高亮
// pre_push_verification()
if any(test, build, lint) failed:
  raise VerificationFailed
  # commit 保留 · push 阻断
  registry.mark_verification_failed(issue_id)

Operator Intent

agent:retry / agent:follow-up / agent:blocked / agent:rebase — 四种 operator intent，按优先级解析为不同 orchestrator 行为。

数字 + 代码

一份 workflow.md
把守护进程跑起来

性能基线 · 6 项关键 KPI
workflow.md yaml · 完整可跑 
---
tracker:
  kind: github
  api_key: $GITHUB_TOKEN
  active_states: [open]

agent:                          # Python 生态示例（也可配 Node/Go/Rust/Java）
  max_concurrent_agents: 5
  test_command: "pytest -x -q"
  lint_command: "ruff check ."

hooks:
  pre_commit: "black --check ."

review_feedback:
  enabled: true
  max_followup_attempts_per_pr: 5
---
orchestrator server start --workflow ./workflow.md
