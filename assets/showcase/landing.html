两个不可替代的核心能力

让 agent 不再只是聊天框

大多数 code agent 的边界是"交互式 IDE 助手"——你提需求，它给代码。下述两个能力是 clawcodex 真正的护城河。

01 / 编排器

自主 issue → PR 流水线

长跑守护进程轮询 issue 跟踪器，复制 workspace，让 agent 接手写代码，跑测试，提交，推送，开 PR——全流程无人值守。每一步可暂停、可接管、可注入提示。

  • 4 个跟踪器适配器（GitHub / Gitee / GitCode / Linear）
  • 状态机：pending / running / synced / completed / failed / abandoned
  • LiveView HTTP/SSE 仪表盘，浏览器直接看 agent 在干啥
  • Takeover：暂停 agent 启动 REPL 人工接管，完事再切回
  • PR 评审自动修复：review 评论 + CI 失败自动迭代同分支
  • 提交前测试门禁：pre-commit / pre-push 跑 pytest 不过不发 PR
  • 重跑标签机制：issue 加 agent:retry 标签自动重跑
02 / SOP 编译器

把工程流程编译成多 agent 团队

把你写的 workflow.md 流程规范，编译成一组可协同的 agent：每个角色一个 agent 定义 + 一个入口 skill + 一张编排图。agent 之间 SendMessage 通信，崩溃后能恢复。

  • SDK 解析器 + skill 分组器 + agent 构建器 + Jinja 模板
  • 输出：agent 定义 · 入口 skill · 编排图（可读、可执行、可观测）
  • Worker 间通过 task-notification XML 路由互相通信
  • 轻量级协调器工具集：Read / WebSearch / WebFetch + Agent / SendMessage / TaskStop
  • 示例：clawcodex-dev sop convert examples/sop/order_processing.md --out ./.clawcodex
四个同样独特的能力

再补四块拼图，工程团队就齐了

在编排器 + SOP 编译器之外，还有四个让 clawcodex 真正能"7×24 跑起来"的能力。

自动化工程闭环

PR 评审自动修复 + 提交前测试门禁。Reviewer 提评论、CI 报错，agent 自动读反馈、迭代修复、加测试、重跑门禁，反复直到过线。

LiteLLM · 100+ LLM 后端

--provider litellm 一行切到任何模型：Bedrock · Vertex · Azure · OpenAI · Together · Anyscale……统一接口、跨 provider 块转换。

分布式 Cron + IM 网关

文件锁 + 抖动调度的 Cron 防重跑；统一 IM 网关接 WeChat / 飞书 / Slack / Discord，REPL 和 Orchestrator 都能挂上去。

三层解耦架构

upstream 源码快照 + capabilities 协议 + clawcodex_ext 下游补丁层。跟上游同步零摩擦，扩展不污染上游。

运行时切换模型

REPL / TUI 内 /provider litellm · /model gpt-4o 即时切。ModelRegistry 热替换，不停会话。

13 态澄清队列

agent 卡住不会干等。3 通道（交互 / 文件 / @提及）求解，13 种状态机走完整，issue 不堵塞也不丢失。

架构总览

三层解耦，扩展不污染上游

src/ 是 upstream 的源码快照（不修改），extensions/capabilities/ 定义层间协议，clawcodex_ext/ + extensions/ 都是下游扩展。同步上游只动 src/，你写的扩展全在扩展层。

extensions/ 下装的具体子系统：orchestrator · sop_converter · im_gateway · visualizer · remote_api
